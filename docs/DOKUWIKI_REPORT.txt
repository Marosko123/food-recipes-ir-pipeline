===== 1. Spracovanie dát a Spark (Wiki Dump) =====

Na spracovanie **20GB Wikipedia XML dumpu** som použil **PySpark** v kombinácii s vlastným **Python streamingom**. Keďže pracujem na **MacBook Pro M4 Pro** (ktorý je síce rýchly, ale 20GB XML v pamäti je stále problém), musel som implementovať hybridný prístup.

**Môj postup:**
  * Skript ''spark_jobs/enwiki_spark_parser.py'' nečíta celé XML naraz.
  * Používam ''bz2'' knižnicu na **streamované čítanie** riadok po riadku.
  * Bufferujem riadky, kým nenájdem tagy ''<page>...</page>''.
  * Tento blok pošlem do môjho parsera ''WikiXMLParser''.

**Regexy, ktoré som použil na extrakciu:**
Na identifikáciu kulinárskych článkov používam sadu regulárnych výrazov. Tu je ukážka priamo z môjho kódu:

<code python>
# Detekcia Infoboxov pre jedlo
INFOBOX_PATTERNS = [
    re.compile(r'{{\s*Infobox\s+food', re.IGNORECASE),
    re.compile(r'{{\s*Infobox\s+prepared\s+food', re.IGNORECASE),
    re.compile(r'{{\s*Infobox\s+ingredient', re.IGNORECASE),
]

# Extrakcia kategórií
_CATEGORY_PATTERN = re.compile(r'\[\[Category:([^\]|]+)(?:\|[^\]]+)?\]\]', re.IGNORECASE)
</code>

Vďaka výkonu **M4 Pro** čipu som dosiahol rýchlosť spracovania cca **2 500 stránok za sekundu**, čo mi umožnilo prejsť celý dump a vyfiltrovať 12 000 relevantných článkov v rozumnom čase.

===== 2. Enrichment a Prepojenie dát (Aho-Corasick) =====

Na prepojenie receptov (5600 ks) s Wiki dátami som nepoužil klasický SQL JOIN (ktorý by bol neefektívny pre fulltextové hľadanie entít), ale **Aho-Corasick algoritmus** (v súbore ''entities/recipe_enricher.py'').

**Môj postup:**
  * Vytvoril som zbierku (automat) zo všetkých názvov Wiki článkov (napr. "Garlic", "Chicken", "Pasta").
  * Pre každý recept som prešiel jeho text (názov + ingrediencie) a našiel výskyty týchto entít v jednom prechode.
  * To mi umožnilo pridať k receptom historický kontext a pôvod ingrediencií (napr. k receptu "Spaghetti" sa pripojil článok o "Pasta" a "Italy").

===== 3. HTML Parser a Heuristiky =====

Pre recepty z ''food.com'', kde zlyhalo JSON-LD parsovanie, som napísal vlastný **HTML fallback parser** (''parser/html_parser.py''). Namiesto ťažkopádnych knižníc som využil rýchle regexy na hľadanie štruktúry v HTML.

**Ukážka mojej logiky pre ingrediencie:**
Hľadám ''<li>'' elementy, ktoré majú v triede slovo "ingredient".
<code python>
self.ingredient_patterns = [
    re.compile(r'<li[^>]*class="[^"]*ingredient[^"]*"[^>]*>(.*?)</li>', re.IGNORECASE | re.DOTALL),
    re.compile(r'ingredients?.*?<ul>(.*?)</ul>', re.IGNORECASE | re.DOTALL)
]
</code>

===== 4. Indexovanie: Architektúra a Polia =====

Prešiel som zo starého vlastného indexera na **PyLucene** (cez Pythonic wrapper **Lupyne**).
  * **Prečo Lupyne?** Umožňuje písať Python kód, ktorý vyzerá ako Python (dict-based), ale na pozadí volá Java Lucene triedy.
  * **Architektúra:** Index je uložený v ''index/v2/''. Používam **BM25Similarity** pre ranking (štandard v priemysle).

**Odôvodnenie jednotlivých polí (fields) v indexe:**

^ Názov poľa ^ Typ poľa ^ Boost ^ Dôvod použitia ^
| ''title_text'' | TextField | 2.0 | Hlavné pole pre vyhľadávanie. Tokenizované (full-text). Najvyšší boost, lebo zhoda v názve je najdôležitejšia. |
| ''ingredients_text'' | TextField | 1.5 | Umožňuje hľadať recepty podľa obsahu ("chicken pasta"). Tokenizované. |
| ''instructions_text'' | TextField | 1.0 | Hľadanie v postupe prípravy (napr. "grill", "bake"). |
| ''wiki_abstracts'' | TextField | 1.0 | Obohatené dáta z Wiki. Zvyšuje recall (nájde "Mexican dish" aj keď to nie je v názve, ale v histórii jedla). |
| ''ingredients_kw'' | StringField | - | **Netokenizované**. Slúži na presné filtrovanie (facets). Napr. filter "obsahuje presne Garlic". |
| ''cuisine_kw'' | StringField | - | Pre filtrovanie podľa kuchyne (Italian, Mexican). |
| ''total_minutes'' | IntPoint | - | Numerické pole pre **Range Queries** (napr. recepty do 30 minút). |
| ''url'', ''docId'' | StoredField | - | Len na uloženie, nevyhľadáva sa v nich. Slúžia na zobrazenie výsledkov. |

===== 5. Implementácia Vyhľadávania a Typy Dopytov =====

**Nový index (PyLucene):**
  * Binárny formát (segmenty), extrémne rýchly seek.
  * Implementovaný v ''search_cli/lupyne_searcher.py''.
  * Podporuje **QueryParser**, ktorý automaticky rozumie syntaxi ako ''"phrase"'' alebo ''AND/OR''.

**Aké typy dopytov (queries) v indexe využívam?**
V aplikácii využívam kombináciu viacerých typov Lucene dopytov:
  - **BooleanQuery:** Základ pre kombinovanie textového hľadania a filtrov. (Príklad: `(title:chicken) AND (cuisine:Mexican)`)
  - **PhraseQuery:** Hľadanie presnej frázy. (Príklad: `title:"chocolate cake"`)
  - **RangeQuery (IntPoint):** Filtrovanie podľa číselných rozsahov. (Príklad: `total_minutes:[0 TO 30]`)
  - **TermQuery:** Presná zhoda pre kategórie/tagy. (Príklad: `ingredients_kw:"garlic"`)
  - **MultiFieldQuery:** Hľadanie jedného výrazu vo viacerých poliach s rôznou váhou. (Príklad: `title:pizza^2.0 OR ingredients:pizza^1.5`)

**Ukážka kódu vyhľadávania:**
<code python>
def search(self, query_text):
    # Multi-field query s boostmi
    query_str = f"title_text:{query_text}^2.0 OR ingredients_text:{query_text}^1.5"
    
    # Pridanie filtrov (BooleanQuery)
    builder = BooleanQuery.Builder()
    builder.add(parser.parse(query_str), BooleanClause.Occur.MUST)
    
    if max_minutes:
        # Range query pre čas
        time_query = LongPoint.newRangeQuery("total_minutes", 0, max_minutes)
        builder.add(time_query, BooleanClause.Occur.MUST)
        
    return self.searcher.search(builder.build(), 10)
</code>

===== 6. Porovnanie: Starý vs. Nový Index =====

Porovnal som výsledky na rovnakých dopytoch. Nový index je nielen rýchlejší, ale dáva relevantnejšie výsledky vďaka BM25 a Wiki dátam.

**Starý Indexer (Phase D):**
  * Písal som ho ručne v Pythone (ukladal ''terms.tsv'', ''postings.tsv'').
  * **Problém:** Bol pomalý pri načítaní a nepodporoval pokročilé dopyty (AND/OR, frázy).
  * Výpočet TF-IDF som robil manuálne: `idf = math.log(self.total_docs / df)`.

^ Dopyt ^ Starý Index (Custom TF-IDF) ^ Nový Index (PyLucene BM25 + Wiki) ^
| ''"grilled chicken"'' | Našiel dokumenty obsahujúce "grilled" ALEBO "chicken". Nevedel riešiť poradie slov (frázu). | **PhraseQuery**: Nájde presnú frázu. Na prvom mieste sú recepty, kde sú slová pri sebe. |
| ''pasta AND italian'' | Ignoroval operátor AND, bral ho ako slovo. | **BooleanQuery**: Nájde prienik množín. Vráti len talianske cestoviny. |
| ''time < 30'' | Nepodporované. | **RangeQuery (IntPoint)**: Vráti recepty s ''total_minutes'' v rozsahu 0-30. |
| ''traditional mexican'' | Slabé výsledky, len ak to bolo v názve. | **Enrichment**: Nájde veľa výsledkov, pretože som k receptom pripojil Wiki abstrakty (kde sa píše "traditional Mexican dish"). |

**Rýchlosť (nameraná na M4 Pro):**
  * **BM25 (PyLucene):** ~16ms / dopyt.
  * **Starý TF-IDF:** ~150ms / dopyt (načítanie CSV do pamäte bolo bottleneck).
